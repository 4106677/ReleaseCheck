# Выбор дизайна отчёта

Статус: два интерактивных прототипа готовы; выбор пользователя ожидается.
Дата: 25 сентября 2026 года. Прототипы доступны после `npm run dev`:

- [A — Review Studio](http://127.0.0.1:5173/design?direction=studio).
- [B — Release Console](http://127.0.0.1:5173/design?direction=console).

Оба варианта имеют одинаковые реальные before/after/diff-изображения fixture.
Результат сравнения — 14 323 изменённых пикселя из 1 296 000 (1,11%) для текущих
подготовленных изображений. Значения получены `pixelmatch`, не нарисованы вручную.
Подготовленные PNG и метаданные хранятся в репозитории, поэтому просмотр дизайна
работает без API/БД; достаточно `npm run dev:web` после установки зависимостей
и сборки пакетов. Основной рабочий демо-сценарий остаётся по адресу `/`.

## Разница

|                   | A — Review Studio                                           | B — Release Console                                     |
| ----------------- | ----------------------------------------------------------- | ------------------------------------------------------- |
| Задача интерфейса | Спокойный просмотр и решение о визуальном изменении         | Последовательное расследование списка проблем           |
| Оформление        | Светлый фон, зелёный акцент, больше свободного пространства | Тёмные панели, голубой акцент, более плотная информация |
| Компоновка        | Сравнение слева, очередь замечаний справа                   | Очередь замечаний слева, сравнение справа               |
| Аудитория         | Разработчики, дизайнеры, небольшие студии                   | Разработчики, регулярно проверяющие релизы              |

Рекомендация: A как основа. Это предложение, не утверждённое решение.
Выбор допускает сочетание деталей, например структуру A с палитрой B.

## Что можно попробовать

- Переключить направление A/B в верхней панели.
- Перетаскивать границу before/after непосредственно по изображению или ползунком.
- Переключить Baseline, Current и Difference.
- Выбрать visual / JavaScript / network issue и прочитать его контекст.
- Открыть Review summary; закрыть мышью или Escape.
- Проверить мобильную ширину: сравнение расположено перед очередью замечаний.

Клавиатура: кнопки и ползунок доступны через Tab, стрелки двигают ползунок,
summary использует native modal dialog с удержанием фокуса и Escape.

## Граница прототипа

Это демонстрационный отчёт с фиксированным ID. Кнопка summary ничего не принимает
и не меняет baseline. Две browser issues в макете — JS-ошибка и HTTP 404;
дублирующее console-сообщение про тот же 404 не показано отдельной проблемой.
Общая группировка реальных findings в приложении ещё не реализована.

Пакет checks теперь умеет сравнивать PNG с одинаковым профилем захвата. Он
возвращает matched/changed, число и долю отличающихся пикселей и diff PNG.
Несовместимые профили/размеры не сравниваются; некорректные пороги и изображения
отклоняются. Профиль включает браузер, OS release, platform, architecture,
viewport и фиксированные параметры рендера. Сохранение baseline и автоматический
вызов сравнения из worker пока остаются следующим этапом.

## Обновление материалов

При работающем fixture и собранных пакетах:

```sh
npm run design:assets
npm run test:design
```

`design:assets` заново снимает исходную и изменённую страницы и создаёт PNG и
metrics.json. При изменении OS/browser профиль изменится; не заменяйте только
один скриншот без второго. `test:design` проверяет обе схемы, мышь/клавиатуру,
смену режимов и мобильную ширину. Снимки проверки лежат в `.local/design-review`.

После ответа пользователя зафиксировать направление здесь и в decisions.md,
затем переносить выбранные компоненты в живой отчёт. До выбора не заменять
существующий рабочий интерфейс одним из вариантов.
